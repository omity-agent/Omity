# 数据存储设计

## 核心实体

```text
sessions
  ├── runs
  │     ├── inputs
  │     └── checkpoints
  │           └── checkpoint_writes
  ├── messages ── input_id（可空）──> inputs
  ├── events ──── input_id ────────> inputs
  └── 会话辅助数据
```

### 会话：`sessions`

保存工作目录、配置 Profile 列表、模型与工具定义快照、创建与更新时间，以及界面刷新版本号。

`control` 是用户请求的执行模式，不是实际运行状态。例如 `pause` 表示请求暂停，实际轮次可能仍在运行并等待安全边界。

### 执行轮次：`runs`

一次连续执行可以消费多条用户输入。轮次拥有唯一的状态和错误：

```text
pending → running ⇄ paused
              └────→ done / canceled
```

一个会话最多有一个 `pending`、`running` 或 `paused` 的轮次，由部分唯一索引保证。

终结的轮次保留，供输入和对话追溯；其检查点和已处理输入的流式事件被清理。

### 输入投递：`inputs`

保存每次提交的原文、所属会话与轮次、轮次内顺序及提交幂等标识。

`delivery` 只有三个值：

- `pending`：尚未投递到执行上下文。
- `consumed`：已经形成用户消息。
- `canceled`：未投递即被取消。

输入不保存执行错误，也不保存另一份运行状态。轮次内的第一条输入由 `ordinal = 0` 标识，无自引用的根节点。

`content` 始终保留提交内容。`messages` 中的内容是对话上下文，可因编辑、分叉或历史同步而变化；两者职责不同，不进行“消费后清空输入正文”的转移。

轮次完成或在执行中取消时，尚未投递的追加输入转入新轮次。恢复期间处理持久化的会话取消命令时，则取消全部活动输入。

### 对话记录：`messages`

保存稳定消息及其上下文排列位置。`message_json` 承载用户、模型、工具消息的不同结构，避免把异构消息拆成大量可空列。

- `id`：数据库主键。
- `source_id`：模型执行使用的消息标识，在会话内唯一。
- `input_id`：用户输入的来源，可空且唯一。
- `position`：当前上下文顺序，在会话内唯一；空值表示不在当前上下文中。

历史消息可以没有输入来源，例如导入的历史、模型回复或工具结果。消息通过 `(session_id, input_id)` 复合外键防止跨会话关联输入。

前端仍使用“输入队列”视图。该视图由 `inputs` 的投递状态与 `runs` 的运行状态组合得到，不是另一套持久化状态。

## 恢复数据

`checkpoints` 每个 `(run_id, checkpoint_ns)` 保存一份当前快照，载荷和元数据使用 BLOB。

`checkpoint_writes` 保存该快照的任务中间写入，通过 `(run_id, checkpoint_ns, checkpoint_id)` 外键指向当前快照。更新快照前删除过期写入。

LangGraph 的 `thread_id` 是轮次 ID 的十进制字符串，仅在适配层使用。数据库内使用整数 `run_id`，不编码或解析会话 ID。

删除会话时通过外键依次删除轮次、输入、检查点和中间写入，无字符串前缀匹配清理。

## 辅助数据

| 表                       | 责任与生命周期                                 |
| ------------------------ | ---------------------------------------------- |
| `events`                 | 活动输入的流式事件，完成后清理，不作为审计日志 |
| `composer_drafts`        | 每会话一份草稿，用版本号防止旧内容覆盖新内容   |
| `host_leases`            | 每会话一份执行进程租约，包含拥有者及到期时间   |
| `hook_usage`             | 会话内每个 Hook 的使用计数                     |
| `tool_cancellations`     | 会话内工具调用的取消请求，完成后清理           |
| `reasoning_translations` | 按消息标识及目标语言保存翻译结果               |
| `file_link_units`        | 正文、推理和工具输入输出中的文件路径识别索引   |

流式事件、翻译和文件链接索引可能先于完整消息落盘，因此其中的消息或文本所有者标识不声明指向稳定消息表的外键。其会话归属，以及可用时的输入归属，仍由数据库约束。

## 访问认证

| 表                     | 用途                       |
| ---------------------- | -------------------------- |
| `credentials`          | WebAuthn 公钥凭据及计数器  |
| `challenges`           | 有期限的注册或认证挑战     |
| `access_sessions`      | 登录令牌哈希及到期时间     |
| `registration_tickets` | 注册许可令牌哈希及到期时间 |

`access_sessions` 是登录会话，与 Agent 对话会话 `sessions` 无归属关系。

## 代码组织

```text
database/
  schema/               表、外键和索引定义
  sqlite/               连接、事务和首次建库
  session/              会话定义快照、初始对话和原文副本
  records/
    session/            会话元数据和草稿
    execution/          输入接收与认领、轮次转换、控制与恢复
    transcript/         消息、流式事件、翻译及文件链接记录
  indexing/             文件链接的增量识别与历史同步
  agentDatabase.ts       面向运行时的数据库操作入口
  maintenance.ts         会话重置和删除
```

业务操作使用事务，例如输入认领与用户消息插入、暂停命令与轮次状态变更、轮次终结与待投递输入交接。外键始终启用；WAL 用于并发读写。

Schema 是建表结构的唯一来源。构建时生成初始化 SQL；运行时只初始化空库，不执行旧库迁移。
